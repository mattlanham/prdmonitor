## Codebase Patterns

### Project Structure
- Entry point: `main.go` with minimal logic, delegates to internal packages
- Data models in `internal/model/model.go`
- Tests use Go's `testing` package with `t.TempDir()` for temp directories
- Config struct pattern for CLI configuration

### CLI Argument Parsing
- `ParseArgs(args []string)` takes os.Args to allow testing
- Returns `*Config, error` pattern for validation
- Errors are printed to stderr, exit code 1 for failures

### Error Handling
- Use `fmt.Errorf` with `%w` for wrapping errors
- Check `os.IsNotExist(err)` for cleaner error messages
- Validate directory is readable by attempting to open it

### Scanner Package
- Use `filepath.WalkDir` for recursive directory traversal (more efficient than `filepath.Walk`)
- Return `*ScanResult` with both files and non-fatal errors
- Convert paths to absolute using `filepath.Abs()` for consistency
- Custom error types (e.g., `NotADirectoryError`) for specific error handling
- Module name is `lanham/prdmonitor` (important for internal imports)

### Parser Package
- `ParseFile(filePath)` returns `*ParseResult, error` - reads and parses a single file
- `ParseBytes(data)` returns `*model.PRD, error` - parses JSON bytes directly (useful for testing)
- `ParseFiles([]string)` returns `([]*ParseResult, []error)` - batch parsing with non-fatal error collection
- Custom `ParseError` type wraps file path with underlying error, implements `Unwrap()` for error chains
- Use `errors.As()` to check for specific error types in tests
- JSON unmarshaling handles missing fields gracefully (zero values)

### TUI Package (Bubble Tea)
- Uses Model-Update-View pattern with `tea.Model` interface
- `App` is the main model, contains `Board` which contains `Column` components
- `tui.Run(parseResults)` is the main entry point - launches the TUI program
- `tui.RunWithWatcher(parseResults, watcher, rootDir)` for file watching support
- `tea.WithAltScreen()` provides clean terminal switching
- `tea.WindowSizeMsg` is used to handle terminal resize events
- `tea.Cmd` pattern for async operations (e.g., listening for file change events)
- Custom message types (e.g., `FileChangedMsg`) for external events
- Lip Gloss styles: use `lipgloss.NewStyle()` for creating styles, chain methods
- `lipgloss.JoinHorizontal()` and `lipgloss.JoinVertical()` for layout composition
- Card component with box-drawing borders using `lipgloss.RoundedBorder()`
- `truncateString()` helper function for text that may exceed display width
- Column colors: Red (203) for Incomplete, Yellow (220) for In Progress, Green (84) for Complete

### Watcher Package (fsnotify)
- `watcher.New()` creates a new file watcher
- `watcher.AddFile(path)` / `watcher.AddFiles(paths)` to watch files
- `watcher.WatchDirectory(rootDir)` recursively watches directory tree for new prd.json files
- Watches parent directories since fsnotify works better with directories
- Filters events to only watched files (ignores other files in same directory)
- `watcher.Events()` returns channel for receiving `Event` structs
- `watcher.Start()` should be called in a goroutine
- `watcher.Stop()` closes the watcher and releases resources
- Debouncing: 100ms between events for the same file to handle rapid saves
- Operation types: `OpModify`, `OpCreate`, `OpDelete`
- Use `defer w.Stop()` in main.go for proper cleanup
- **Path Resolution**: Use `filepath.EvalSymlinks()` to resolve symlinks for consistent path comparison
  - Critical on macOS where `/var` is symlink to `/private/var`
  - fsnotify reports resolved paths, so stored paths must also be resolved
- **New File Detection**: `WatchDirectory()` enables detecting new prd.json files
  - Watches all subdirectories recursively
  - Detects new directories and adds them to watch list
  - Only emits events for files named exactly "prd.json"
- **Debounce Ordering**: Check operation type BEFORE debouncing
  - Prevents irrelevant events (like CHMOD) from affecting debounce timing for WRITE events

### Card Component Pattern
- Separate `card.go` file for the Card component per AGENTS.md project structure
- `Card` struct holds `ProjectName` and `Story` (model.UserStory)
- `NewCard(projectName, story)` constructor for creating cards
- `Card.Render(width)` method returns styled string output
- `CardStyle` struct for customizable styling (border, project, ID, title, description colors)
- `DefaultCardStyle()` provides sensible defaults
- `RenderWithStyle(width, style)` for custom styling
- Card layout: Project name at top, Story ID (prominent), Title (bold), Description (truncated)

### Read-Only Interface Pattern
- Use constants for status messages (e.g., `ReadOnlyMessage`, `EditHelpMessage`) for testability
- Status bar at bottom shows mode indicator and shortcuts
- Include helpful message guiding users to edit source files directly
- Explicitly handle and ignore edit-related keybindings (e, i, d, x, enter, backspace, delete)
- Return `nil` cmd from Update() to indicate "no action" for ignored keys
- `tea.KeyMsg` has specific types: `tea.KeyEnter`, `tea.KeyBackspace`, `tea.KeyDelete` vs. `tea.KeyRunes`
